# V2 修订历史方案的可移植提取

这里的 **V2** 指修订历史的数据与交互契约，不只是 `Y.encodeStateAsUpdateV2` 的二进制格式。完整状态用于恢复；同源的规范化 Tiptap JSON 用于列表后的详情、只读预览和差异计算。

## 前后端边界

| 边界 | V2 行为 |
| --- | --- |
| 协同写入 | 正文在 `Y.XmlFragment('default')`，标题在 `Y.Text('title')`。当前状态持久化时同步写完整 V2 state、JSON、标题、语义哈希与修订计数。 |
| 自动物化 | 当前状态完成持久化后安排延迟修订；最后连接断开可提前物化。按正文哈希加标题去重，写入时再次检查。 |
| 手动创建 | `POST /api/revisions/create` 保存同一组 V2 字段，允许内容相同的命名版本。它是写入 API，不属于只读历史组件的内部操作。 |
| 列表 | `GET /api/revisions/list` 按 `(version DESC, id DESC)` 使用不透明游标分页，传输元数据、可用性与可恢复性，不传正文。 |
| 详情 | `GET /api/revisions/detail` 优先返回持久化 JSON；`id=current-<documentId>` 是当前文档的虚拟详情。旧记录只有完整 state 时可按需解码。 |
| 前端查看 | 历史内容在独立只读视图中渲染。两份详情基于同一 schema 做结构和文字差异；打开历史时锁定实时编辑区。 |
| 恢复 | `POST /api/revisions/restore` 读取目标版本的原始完整 V2 state，替换当前状态，并让在线客户端收到 `document.reset` 和 WebSocket 4205 后重建文档。恢复响应仅 `{ id }`。 |

新写入修订的 `sourceFormat` 是 `v2_json`，这表示修订行包含规范化 JSON，**也保留完整的 Yjs V2 state**。轻量 `Y.encodeSnapshotV2` 产物不含独立可恢复的正文，不能替代 `state`。

## 公开示例的适配层

本仓库用本机文件、单进程串行队列和简单 WebSocket 传输演示以上边界。延迟窗口为方便演示而缩短，实际系统使用持久化队列和更长的环境配置窗口。实际系统的数据库事务、分布式任务队列、Hocuspocus 房间、文档 Token 鉴权、多实例驱逐及离线 IndexedDB 清理没有直接移植。OpenAPI 修改产生的 `open_api` 修订及修改前 `protect` 版本也没有公开端点，接入时应与同一 V2 写入合同对齐。示例 WebSocket 的 `epoch` 是防止旧连接回灌的本地传输围栏，**不是 V2 REST 契约字段**；V2 客户端重建的可观察信号仍是 `document.reset` 与 4205。

示例的语义哈希只针对公开 StarterKit schema，不能与不同 schema 的业务系统哈希互换。前端差异比较也仅覆盖示例 schema，不承诺富媒体节点或内容作者归属。没有可靠的逐处归属时，应显示中性差异，不应把快照创建人推断为文字作者。示例没有软删除模型，因此不会产出 `deleted` 可用性状态；已验证损坏的旧 state 在示例中不再标记可恢复，这是比仅检查 state 是否存在更严格的本地安全判断。

示例没有鉴权，默认只监听 `127.0.0.1`；不应直接部署到公网。生产 API 使用文档 Token 识别真实文档并判断读写权限，查询参数 `doc_id` 只是路由键。

## 恢复保护的差异

源方案的 `pre_restore` 与恢复审计写入是尽力而为，失败会记录但不阻断主恢复。本参考实现选择 **恢复前保护版本必须成功持久化** 才继续，这是明确的安全性强化。恢复后记录 `restore` 行和来源版本。读者如需保持源系统完全一致的失败语义，应在接入其持久化与审计链路时单独决定。

## 验收依据

- 从同一 Y.Doc 派生的 state、JSON、哈希、标题与 schema 版本在重启后仍一致。
- 同语义但不同 Yjs 更新字节的正文不会产生重复自动版本；手动建版不判重；标题单独变化也会产出新版本。
- 列表游标、虚拟当前版本、旧数据可用性、跨文档隔离和缺失正文的行为可测试。
- 历史视图不能修改实时文档；差异可表达基础文字、格式、节点与标题变更。
- 恢复留存恢复前状态和来源记录，在线客户端仅重建一次，旧连接不能重新合并已恢复的正文。
